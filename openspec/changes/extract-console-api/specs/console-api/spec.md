## ADDED Requirements

### Requirement: Source package and mock identity

The system SHALL expose `@in-falcone/console-api` as private ESM TypeScript source, with per-module
subpath exports and relative internal imports. The core SHALL import without window, React or
React DOM. The app SHALL depend on the package through `workspace:*`, with no moved-module
re-export shims, no definitions of requestJson, requestConsoleSessionJson, listAccessibleTenants
or listAccessibleWorkspaces, and no literal `in-falcone.console-shell-session` under its src.
The package Vitest default SHALL be node; browser tests MAY select jsdom per file. The app's
Vitest settings SHALL remain unchanged. Config's import.meta.env reads SHALL remain unchanged.

#### Scenario: Existing app mocks intercept extracted collaborators

- **WHEN** the app mocks a package http or session subpath
- **THEN** relative imports within auth, loaders and permissions resolve to the same module ID
- **AND** the app suite retains the same file and test counts as base `7acbac0`

### Requirement: Session storage compatibility

The system SHALL preserve the full auth exports and legacy session format, including the keys
`in-falcone.console-shell-session`, `in-falcone.console-protected-route`,
`in-falcone.console-auth-status-hint` and event `in-falcone:console-session-invalidated`.

#### Scenario: A base session survives extraction

- **GIVEN** the synthetic JSON snapshot generated by base `7acbac0` persistConsoleShellSession
- **WHEN** the package reads that value from sessionStorage
- **THEN** the resulting snapshot is deep-equal to the base value

### Requirement: Legacy HTTP headers and refresh limits

The transport SHALL send Accept and Content-Type application/json, X-API-Version `2026-03-26`
and an X-Correlation-Id prefixed `corr_`. A default GET SHALL omit Idempotency-Key; GET with
idempotent true and every POST, PUT, PATCH and DELETE SHALL send an `idem_` key.

#### Scenario: A rejected access token refreshes exactly once

- **GIVEN** an active session with access expiry more than 60 seconds away and a valid refresh token
- **WHEN** the first authenticated GET returns 401 and refresh succeeds
- **THEN** exactly one refresh POST and one request retry use the new Bearer token
- **AND** a 401 on that retry is rethrown without another refresh

#### Scenario: Refresh failure invalidates the session

- **WHEN** refresh fails with 429, 504 or retryable true
- **THEN** exactly two refresh POSTs occur
- **AND** a terminal 400 instead causes exactly one refresh POST
- **AND** both clear the session key, persist the login hint, dispatch the legacy event and rethrow
  the original request's 401

#### Scenario: Near-expiry access has no usable refresh token

- **GIVEN** access expiry within 60 seconds and a missing or expired refresh token
- **WHEN** an authenticated request is attempted
- **THEN** no fetch occurs and HTTP_401 is thrown

### Requirement: Shell loaders and bounded client set

The package SHALL export typed clients only for the seven existing auth endpoints and GET
`/v1/tenants`, GET `/v1/tenants/{tenantId}` and GET `/v1/workspaces`. All request URLs SHALL be
same-origin relative `/v1/` paths without `://`. Routed-page clients SHALL remain deferred until
an endpoint inventory is available or their page migration specifies them.

#### Scenario: Tenant operators load only their tenant IDs

- **WHEN** listAccessibleTenants receives tenant operator IDs a and b
- **THEN** it requests the two singular tenant paths and never the collection
- **AND** an empty ID list returns an empty collection without a request

#### Scenario: Platform and workspace collections preserve parameters

- **WHEN** a platform user loads tenants or workspaces
- **THEN** parsed URLSearchParams contain page[size] equal to 100 and sort equal to displayName
- **AND** workspaces additionally contain filter[tenantId] equal to the requested tenant ID

### Requirement: Synthetic fixtures

The package SHALL supply fresh typed synthetic response fixtures per client. The test validator
SHALL recursively walk objects and arrays, reject strings starting with eyJ, and reject strings
under keys matching `/token|password|secret|credential|apikey/i` unless prefixed `synthetic-`.
It SHALL exempt tokenType only when Bearer, and keys ending in Ttl, MaxAge, ExpiresAt or ExpiresIn;
JWT-shaped strings SHALL be rejected even under exempt keys.

#### Scenario: Validator accepts policy metadata and rejects credential-shaped data

- **WHEN** fixtures contain accessToken synthetic-a or recoveryTokenTtl PT15M
- **THEN** validation succeeds
- **AND** refreshToken abc, nested arrays containing password x and eyJ-prefixed values fail

### Requirement: Existing delivery gates include package validation

The existing web-console CI job SHALL run `pnpm --filter @in-falcone/console-api test` as a required
step without continue-on-error. Frozen installation, Vite bundling and the unchanged Dockerfile
workspace dependency filter SHALL include this package.

#### Scenario: A package regression fails CI

- **WHEN** a package test is deliberately made to fail
- **THEN** the web-console CI job fails before delivery
